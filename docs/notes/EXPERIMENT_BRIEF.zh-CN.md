# ISBI 2027 实验规划

> 内部笔记（非汇报终稿）。对外请用 [`docs/reports/EXPERIMENTS.zh-CN.md`](../reports/EXPERIMENTS.zh-CN.md)。


AutoRecon 面向胎儿脑 MRI 长流程：一句话需求 → 可确认的工具计划 → 确定性重建/配准等 → 证据报告。已有系统能跑；本规划要回答的不是「有没有工具链」，而是：**未见口令能否变成正确、最小、可执行的计划，越界能否挡住且不误伤合法步骤，以及计划正确时工具是否真的跑完。**

目标会议：IEEE ISBI 2027，4-page paper。当前实验均为设计中（`idea`），尚无论文结果数字。

## 现有医学影像 Agent 做了什么，和本系统的差别

叙述顺序：别人已经做成什么 → 四项逐条对比（长度、权限、停步、报告）→ 哪一条能当本篇创新、哪一条不能。

### 别人已经做成什么

医学影像 Agent 的共同模式是：**大模型当调度员，调用若干专用视觉工具，再把工具输出汇总成回答或报告。** 代表工作可以分成三类，工具链都短、且以「看图答题」为主：

| 系统 | 模态与输入 | 实际工具链 | 评测在测什么 |
| --- | --- | --- | --- |
| MMedAgent | 一张图 + 一句话；X-ray/CT/MRI/病理等 | 约 6 个工具、7 类任务：VQA、分类、检测、分割、胸片报告、检索增强 | 选对工具、任务分数高 |
| MedRAX | 一张/一组胸片 + 复杂临床问题 | ReAct 循环调用分类、分割、定位、VQA、报告生成等；ChestAgentBench 含诊断题 | 多步推理后选择题是否答对 |
| FetalAgents | 胎儿超声（平面/视频） | Coordinator → 平面分类、分割、生物测量 → Summarizer 临床报告；可对照生长曲线百分位 | 超声测值和报告是否完整、合理 |

它们已经证明：**Agent 可以调医学工具。** 再宣称「首次让大模型调用工具」站不住。差别不在「会不会调工具」，而在工具之间有没有必须守住的长依赖，以及模型有没有权直接把工具跑完、把报告写成诊断。

### 1. 为什么说我们的流程长

「长」不是工具个数多几个，而是 **步骤之间有硬依赖、单步是重计算、中途停错会空转 GPU。**

- MMedAgent / MedRAX：典型路径是「读一张图 → 调 1–3 个分析工具 → 生成答案」。工具大多可并行或任选，没有「必须先重建 3D 才能配准」。一次调用通常是秒到分钟级的前向推理。
- FetalAgents：比问答 Agent 完整（感知→测量→报告），但仍是超声平面/生物测量链路，不是多栈 MRI 的三维重建。
- AutoRecon：一条必须按序发生的六步合同：

```text
多组 BTFE 栈
  → 脑提取
  → 三维重建（FROST 等，容器/GPU，分钟到小时）
  → 配准到孕周图谱
  → 组织分割 → ROI → 表面
```

后一步吃前一步的 NIfTI。只说到配准却把 tissue 跑了，就是过度执行；说到配准却没重建，下游全是空的。这是长流程，不是「工具菜单更长」。

### 2. 别人的模型权限是什么

| | 模型可以做什么 | 模型不可以 / 通常不会做的 |
| --- | --- | --- |
| MMedAgent | 训练成 action planner：直接输出工具名和参数，执行后把工具结果写进最终回答 | 没有「先给人确认再动 GPU」的硬门；报告工具（ChatCAD）可被选来生成临床向胸片报告 |
| MedRAX | GPT-4o 等骨干做 ReAct：自己决定下一跳调哪个工具，包括报告生成，用来支撑诊断类问题 | 工具调用由模型循环驱动，不以用户确认作为执行开关 |
| FetalAgents | Coordinator 分派专家；专家模型出结构化测量；Summarizer 汇总成临床报告 | 设计目标就是出报告，不是把 LLM 锁在「只准排计划」 |
| AutoRecon | 只解析口令、生成受白名单约束的计划、写拒绝码、基于 Evidence Bank 改写叙述 | **不执行任意 shell、不替代重建算法、不编路径/孕周、计划未确认不开 GPU** |

一句话：别人的模型常常 **有权选工具并立刻跑、并把结果说成答案**；这里的模型 **无权跑影像，只无权之外的计划权。**

### 3. 别人能不能「做到某一步就停」

能停，但停的含义不同。

- 问答/胸片 Agent：用户没问分割，就不调 MedSAM。这是 **按问题选工具**，不是截断一条有序流水线。MedRAX 在 ReAct 里觉得答案够了就会停，停点由模型判断，不是用户写死的 `execution_steps` 上界。
- FetalAgents：不问生物测量可以不调测量专家。同样是任务选择，不是「重建做完、配准不要做」。
- AutoRecon：六步是前缀合同。口令说「做到配准」，`execution_steps` 上界就是 registration；再往后跑记为 OverExecution，没跑到记为 UnderExecution。导入已有结果、只展示某几步，也是显式范围，不是模型自己收束。

所以：别人支持「不问就不调」；我们支持并要评测的是 **有序长链上的显式截断 + 复合口令里截断合法前缀、拒绝非法后缀。** 这才是 EXP-001/002 的对象。

### 4. 报告边界别人怎么处理？能不能当创新点？

别人多半把报告当成 **要完成的临床任务**：

- MMedAgent 把 Medical Report Generation 做成工具（ChatCAD，MIMIC-CXR）。
- MedRAX 用报告工具辅助答题，Benchmark 类别里包含 diagnosis。
- FetalAgents 明确走临床报告，并用 WHO 生长曲线做百分位 sanity check——有常模时 **允许** 写发育相关结论。

AutoRecon 相反：没有可靠 GA 常模和专家诊断金标时，**禁止** 写正常/异常/百分位；LLM 只能改写 Evidence Bank 里已有的技术陈述，编造则回退模板。

**不宜把「我们不诊断」单独写成 4-page 创新。** 这是能力边界和安全策略，审稿人会看成局限或合规，不是方法贡献。它的用处是：让「拒绝诊断但保留重建」成为可测的 gold（EXP-002），而不是把拒绝率当分数。

Evidence Bank、陈述校验、专家盲评（EXP-003）可以成为 **下一篇** 的报告创新；本篇 4-page **不把它当主贡献。** 本篇能辩护的差异是：长依赖 MRI 流水线上的受约束 DAG，以及校准拒绝（挡住越界、留下合法步骤）。

### 收到本篇要证明的三句话

别人：短工具链上选对工具、答对题、写出临床向报告。  
我们：长合同链上计划对、停步对、拒绝校准，并且计划能在真实队列里跑完。这对应下面的 EXP-001、EXP-002、EXP-004。

过执行、欠执行、故障传播和两个创新点的定义见 [DEPENDENCY_CHAIN.zh-CN.md](DEPENDENCY_CHAIN.zh-CN.md)。

## 为什么做

再宣称「首次让大模型调用工具」站不住。难点在长依赖、口令夹杂做不到的事、做错一步会空转 GPU。现有工程验证不能直接当论文：开发语料会泄漏，拒绝清单和产品设计同构，也不能证明公开可复现。

因此要做一个**可公开、可冻结、专家约束为 gold** 的基准，而不是再测一遍内部稳定性套件。

## 目的（一篇短文只证明三句话）

1. **听懂并排对。** 未见自然语言能否变成语义正确、不过度执行的任务计划（DAG）。
2. **拒绝要校准。** 危险/不可执行动作要挡住，复合口令里的合法影像步骤要留下。不是拒绝越多越好。
3. **计划能落地。** 在真实单中心队列上，FROST 六步能否跑到合同终态；典型故障能否隔离。这是旁证，不宣称临床质量或最佳重建。

不证明：首次 tool-agent、自动诊断、QC 敏感性/特异性、四后端谁最好、报告已达放射科水平。问题定义见 [DEPENDENCY_CHAIN.zh-CN.md](DEPENDENCY_CHAIN.zh-CN.md)。

## 实验怎么排

| | 4-page 角色 | 测什么 | 主终点 |
| --- | --- | --- | --- |
| EXP-001 FetalMR-FlowBench | **主实验** | 未见口令 → 计划 | `StrictPlanSuccess` |
| EXP-002 安全切片 | 同一基准的安全面，**不是第二贡献** | 阻断 + 保留合法子目标 | `SafeUsefulSuccess` |
| EXP-004 队列旁证 | **短旁证** | FROST 上 L0 合同 + 2–3 类 L0 故障示范 | 描述性 L0 `TechnicalRunSuccess`；不进 Holm |
| EXP-003 报告盲评 | **不进本篇** | Evidence Bank 是否降低无依据陈述 | 留给更长文 |

对照（001/002）：Rules-only、Direct LLM、Structural Validator、Full AutoRecon；GLM 与 Qwen 两个模型。**确认性比较只有一条：Full vs Structural Validator**（避免 Direct LLM 因 JSON 失败被夸大）。其余为描述。

Gold 是专家写的**约束**（必须做到哪一步、禁止什么、必须拒绝哪类），不是唯一 DAG。评价看约束是否满足。

## 怎么做、卡在哪

```text
台架（runner / evaluator）     现在可做，不等专家
专家审「口令 + 约束」          001/002 在此等待
锁 test（一致性达标才进）     不凑预设条数
一次跑 001 + 002              同一份 locked 输出
004 可与专家审并行            吃队列，不吃口令 gold
003 放 4-page 之后
```

建设上限可到约千条请求；**正文只报专家双标一致性达标后冻结的 locked test**，不把建设上限当承诺样本量。旧开发语料和 20+20 稳定性套件不进 locked test。安全子集必须含现有产品模板里没有的 held-out 越界。

专家材料是口令+约束表，不是预画 DAG 打勾。台架、去路径、evaluator 可自动；naturalistic 口令和 gold 不能全自动。

## 怎样算做成

- 语料、约束、split、模型、终点先冻结再跑；不按测试结果回改 gold。
- 统计单位是任务，不是三次重复。确认性两条假设做 Holm 校正，并报 95% CI。
- 公开去标识请求、约束和 evaluator。
- 004 只报 L0 合同通过率，不报解剖/临床质量、不做 L1 寻优。分层见 [QC_PLAN_VS_CURRENT.zh-CN.md](QC_PLAN_VS_CURRENT.zh-CN.md)。
