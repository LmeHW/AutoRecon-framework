## 设计

### 1. 新颖性边界

已有工作已经覆盖医学工具选择、胸片 Agent benchmark、胎儿超声多 Agent 分析和通用医学研究工作流：

- [MMedAgent](https://arxiv.org/abs/2407.02483)
- [MedRAX / ChestAgentBench](https://arxiv.org/abs/2502.02673)
- [FetalAgents](https://arxiv.org/abs/2603.09733)
- [AutoMedBench](https://arxiv.org/abs/2606.01961)
- [Agent Planning Benchmark](https://arxiv.org/abs/2606.04874)

因此本实验不以「Agent 调工具」作为单独创新。拟验证的区别是：面向胎儿脑 MRI 长流程，把自然语言解析、可验证 DAG、真实工具终态、故障恢复和证据报告放在同一个可执行 benchmark 中。

### 2. FetalMR-FlowBench 语料

目标规模为 1000 条请求、700 个独立语义任务：

| 子集 | 请求数 | 独立语义任务 | 构建方式 |
| --- | ---: | ---: | --- |
| Naturalistic | 200 | 200 | 专家根据真实工作场景自由书写 |
| Compositional | 600 | 300 | 每个潜在任务规格由两种独立语言表达实现 |
| Safety / Adversarial | 200 | 200 | 越界、缺输入、矛盾请求、prompt injection 和不可实现任务 |

按潜在任务分层拆分，不允许同一任务的改写跨 split：

- development：100 条；
- validation：100 条；
- locked test：800 条。

现有语料只作旧开发语料，不进入上述 1000 条或最终统计。正式建集前先解决 INV-007 中语料条数冲突；冲突未解时不引用旧语料规模作为论文结果。

每条 benchmark 记录至少包含：

```text
task_id
utterance_id
split
initial_state
expected_disposition
required_outputs
optional_outputs
forbidden_actions
required_refusal_codes
required_and_allowed_tools
missing_inputs
acceptable_intent_constraints
acceptable_plan_constraints
executable_evaluator
```

真实路径改为符号化资源 ID。孕周以整数天标注。对存在多个正确 DAG 的任务记录约束集合，不强行指定唯一序列；对语义不足的请求允许 `CLARIFY_OR_BLOCK` 作为 gold。

### 3. 标注与冻结

- 三位胎儿 MRI 专家参与；某位专家编写的请求由另外两位独立标注。
- 在共识裁决前保存两份原始标签并计算一致性。
- 开发者只能把专家语义标签编码为 evaluator，不得根据系统输出修改 gold。
- test split、模型配置、prompt、规则、主要终点和排除规则冻结并记录 hash 后才能运行。
- 去标识请求、gold 约束和 evaluator 在投稿时公开。

### 4. 对照和模型

四个系统条件共享同一工具说明、输入事实和输出预算：

1. `Rules-only`：现有确定性 fallback。
2. `Direct LLM`：给出工具说明，但关闭结构校验、安全后处理和 fallback。
3. `Structural Validator`：启用 JSON Schema、已知工具、无环和依赖闭包校验，不启用能力边界门禁。
4. `Full AutoRecon`：再启用能力白名单、缺失输入门禁、拒绝策略和安全 fallback。

模型配置：

- 主模型：`glm-5.3-flash`，固定 API 模型字符串、temperature=0、max output tokens=4096。
- 独立模型：`Qwen/Qwen3-32B-AWQ`，固定模型 commit、推理框架版本、`enable_thinking=false`、greedy decoding、max output tokens=4096。
- 两个模型均运行 locked test；LLM 条件每条运行 3 次，rules-only 运行 1 次。
- 非 Full 条件只离线评价计划，不执行其可能危险的动作。

### 5. 指标定义

`IntentConstraintSuccess`：以下 gold 约束全部满足：execution mode、execution/display/report scope、backend、GA/atlas、缺失字段、required refusal set。

`DAGSemanticSuccess`：同时满足：

- 节点全部属于注册工具；
- 图无环且依赖闭包正确；
- 所有合法必需输出从 initial state 可达；
- 不包含 forbidden action；
- 不包含不属于任何最小合法计划的额外计算步骤。

其它指标：

- `OverExecution`：出现明确禁止或不必要的计算节点。
- `UnderExecution`：任一合法必需输出不可达。
- `StrictPlanSuccess = IntentConstraintSuccess AND DAGSemanticSuccess`。
- `RobustSuccess@3`：同一 utterance 的三次输出全部达到 StrictPlanSuccess。
- `ParaphraseConsistency`：同一潜在任务的不同表达得到语义等价计划；比较图约束，不比较 JSON 字符串。

主要终点为 `StrictPlanSuccess`。分项指标、字段 macro-F1、延迟、token 和调用成本为次要终点。禁止使用人为加权的综合分数替代分项结果。

### 6. 统计

- 统计单位为独立 `task_id`；改写和重复运行嵌套在 task 内，不作为独立样本。
- Full 与各对照的配对二分类结果使用 McNemar 检验。
- 以 `task_id` 聚类做 10,000 次 bootstrap，报告绝对差、相对风险和 95% CI。
- 双 backbone 使用 mixed-effects logistic model：`outcome ~ system_variant * backbone + (1 | task_id)`。
- API 超时、无有效 JSON 和模型失败默认按失败计；全局服务中断只能按预注册规则整批原配置重跑并单独报告。

## 不在范围内

- 不使用开发语料作为锁定测试集。
- 不把三次重复当成三倍样本量。
- 不要求模糊请求只有唯一字符串或唯一 DAG。
- 不与不同任务、不同工具空间的外部 benchmark 直接比较准确率。
- 不根据测试结果回改 gold、prompt、阈值或主要终点。
