## 设计

### 1. 病例和场景

- 按孕周和 source stack 数预先分层抽取 60 例去标识病例。
- 每例生成一个真实 Evidence Bank 和一个结构化故障版本，共 120 个自动审计场景。
- 故障版本不修改原始影像，均衡覆盖：步骤失败、几何不一致、可疑配准、缺少 atlas/label map、无常模却请求百分位、证据数值冲突。
- 从 120 个场景中预先随机抽取 30 个真实、30 个故障场景进入专家盲评。

### 2. 四种报告条件

1. `Template`：确定性模板，不调用 LLM。
2. `Flat-LLM`：LLM 读取扁平化但信息等价的步骤事实。
3. `Evidence-LLM`：LLM 读取 Evidence Bank，但关闭输出 validator 和 fallback。
4. `Full`：Evidence Bank + LLM + statement validator + 必要时模板 fallback。

四种条件使用相同事实字段和相同输入/输出预算。两个 LLM backbone 延续 EXP-001 的冻结配置。自动审计覆盖全部场景与条件；三名专家盲评预选场景的四种匿名报告，条件名隐藏、顺序随机。

### 3. 原子陈述审计

每个可验证原子陈述标为：

```text
SUPPORTED
CONTRADICTED
UNSUPPORTED
UNVERIFIABLE
```

`AnyMaterialError`：报告至少包含以下之一：数值或单位错误、与 evidence 矛盾、无证据诊断/正常性/百分位/最佳后端结论、遗漏关键 FAIL/REVIEW/未满足请求。

`EvidencePrecision`：SUPPORTED 原子陈述数除以全部可验证原子陈述数。

`CriticalEvidenceRecall`：已明确呈现的 mandatory evidence 数除以 gold mandatory evidence 数。Mandatory evidence 固定包括 FAIL、REVIEW、缺失文件、未满足请求、无常模和步骤未完成。

`NumericExactness`：单位标准化后与 Evidence Bank 数值完全一致的数值陈述比例。

`BoundaryViolationRate`：诊断、正常/异常、百分位、最佳后端等越界陈述比例。

`TraceCoverage`：具有明确 evidence ID 的可验证陈述比例。

主要终点为报告级 `AnyMaterialError` 和 `CriticalEvidenceRecall`。

### 4. 专家盲评

三位专家依据预先定义锚点的 5 级量表评分：

- 事实正确性；
- 关键证据完整性；
- 表达清晰度；
- 证据可追溯性；
- 用于研究复核的可用性。

同时记录核对报告所需时间。专家查看对应的结构化事实和必要的 Dashboard 证据，但不要求对正常/异常作诊断。

### 5. 统计

- Full 与 Flat-LLM 的 AnyMaterialError 为确认性配对比较；用 McNemar 检验和病例聚类 bootstrap 95% CI。
- EvidencePrecision、CriticalEvidenceRecall 和 NumericExactness 报告病例级分布与配对差。
- 序数评分使用 cumulative-link mixed model，方法为固定效应，病例和阅片者为随机效应。
- 共识前的评分一致性使用 Krippendorff's alpha；二分类错误标签同时报告百分比一致率。
- 核对时间报告 median/IQR，并使用考虑病例与阅片者的混合模型或预注册的配对非参数检验。

## 不在范围内

- 不称为自动临床报告，不评价诊断准确率。
- 不把技术报告与真实放射科诊断报告做等价比较。
- 不使用系统自身或同一 LLM 作为唯一事实裁判。
- 不把可读性提升解释为事实正确性提升。
